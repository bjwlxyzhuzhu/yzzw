## 二、赛道选择：智能体设计应用组

平台本身就是多智能体系统，与本组的考察要点逐一对应：

| 本组考察 | 平台已有能力 |
|---|---|
| 任务执行能力 | 研课八步：教研组长智能体分派任务，各角色起草、质询、修订、评审，形成教案、大纲、试卷等成果 |
| 交互服务能力 | 演课场：教师智能体授课，40 位学习者智能体自主提问、质疑、讨论；教师可随时以教师或学生身份插话 |
| 专业支撑能力 | 依据导入的教材讲义逐个语言点研讨；引用须注明出处，无出处的标“待核查”；对照中文水平等级标准检查难度 |
| 场景覆盖 | 教科研支持（集体备课）、评价反馈（课堂反馈报告）、教学管理（产物库、流转、研究数据导出）、学习服务（数字客服“思思”） |

不选资源创作组的理由：平台的价值在“过程”（备课—试讲—反馈—修订闭环），而不是单个资源成品。

## 三、应用人群与场景

1. **国际中文教育专业硕士（汉硕）、本科生**：缺少真实海外课堂的试讲机会。可在演课场面对不同母语、不同水平的学习者智能体反复试讲，预演偏误与文化误解，再依据反馈回研课场修改教案。
2. **高校国际中文教育学院、来华留学生教学单位的教研室**：用研课场组织集体备课，生成符合等级标准的教案、试卷与课件，研讨过程可导出作为教研记录。
3. **孔子学院、中文工坊、海外本土中文教师**：远程参与集体备课；本土化教学顾问智能体提示当地学习者的母语背景和课时条件。
4. **教学研究者**：课堂事件、发言类型、偏误与互动数据可按研究口径导出（模拟数据，须标注为模拟）。

## 五、提交前还需要团队完成的事

1. **单位推荐表**加盖公章；**原创与合规承诺书**签字。
2. 在“爱中文”学习社区专题页**注册并填写报名信息**；同时申请知识图谱与语料库 API 权限。拿到接口文档后，可作为“知识源”接入研课场。服务器端保存密钥，不进入页面。
3. 准备**一份真实的国际中文课例**（如某册教材的一课），导入后跑一遍完整的研课 → 演课 → 反馈闭环，作为演示内容。
4. 在管理员后台配置大模型（本版本数据目录是新的，尚未配置模型；未配置时只能用本地演示模式）。
5. 录制**操作演示视频**（沿用此前的录屏与动画流程，换成国际中文课例与新配色）。
6. 撰写**作品综合说明**：设计思路、智能体架构、AI 技术应用、数据与隐私保护、试点情况。只写真实发生的情况。
7. 支撑材料：已有的教学应用证明、截图、测试记录等。

## 六、收费模式建议（面向高校）

| 项目 | 方式 | 说明 |
|---|---|---|
| 年度机构授权 | 按教师席位分档，一年一签 | 平台已支持：签发 `license.json`，限制席位与有效期 |
| 大模型用量 | 积分制，按实际调用结算 | 平台已有积分账本：预占、结算、冲正，管理员可分配 |
| 私有化部署与实施 | 一次性服务费 | 部署到学校服务器或校内云；数据留在学校 |
| 培训与教研服务 | 按次或按学期 | 教师工作坊、课例共建 |

定价请按成本测算：服务器、模型调用、实施与维护人力，再参考同类教学平台的采购价格。高校采购通常走合同与发票流程，不需要在平台内接入在线支付。

签发授权示例（平台方操作，私钥在代码目录之外）：

```
node server/cli.js license-issue --key C:/Users/Administrator/.yanzhi-license/yanzhi-license-private.pem --licensee 某某大学国际教育学院 --seats 50 --expires 2027-09-30 --out license.json
```

学校管理员在后台“概览 → 机构授权”上传该文件即可。
